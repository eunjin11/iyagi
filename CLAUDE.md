## Architecture

**iyagi** is a mobile-first text game engine with a custom DSL (`.iyagi` files) and a React play engine.

### Story Pipeline

1. **`.iyagi` DSL** → parsed by Langium (`src/language/parseIyagi.ts`) → AST → converted to `Story` object (`src/language/astToStory.ts`)
2. At **build time**, the Vite plugin in `vite.config.ts` transforms `.iyagi` files to JSON
3. `src/story/current.ts` imports all `src/scenarios/*.iyagi` files — the first one becomes the active story
4. The `Story` object (`src/story/types.ts`) is the canonical runtime format: `{ title, start, init, varDefs, scenes }`

### Core Engine

- **`useStoryEngine`** (`src/hooks/useStoryEngine.ts`) — top-level hook combining play + save/load
- **`useStoryPlay`** (`src/hooks/useStoryPlay.ts`) — wraps `useReducer(storyReducer, ...)` and exposes `{ scene, currentStep, pastTexts, choices, vars, advance, choose }`
- **`storyReducer`** (`src/story/storyReducer.ts`) — state machine. Events: `TAP_ADVANCE`, `SCRIPT_DONE`, `SET_SNAPSHOT`, `RUN_SCRIPT`, `CHOOSE`. State shape: `{ sceneId, stepIndex, vars, storyLog }`
- **`useSaveEngine`** (`src/hooks/useSaveEngine.ts`) — persists snapshots to `localStorage`

### Action System

Scripts in `.iyagi` files execute via `new Function(...)` (see `src/actions/index.ts`). Built-in actions: `jump(sceneId)`, `set(key, val)`, `inc(key, n)`, `dec(key, n)`. Variables declared in `vars:` auto-generate helpers: `setHp(v)`, `addHp(n)`, `subHp(n)` for numbers; `toggleAlive()` for booleans. Custom domain actions live in `src/actions/customActions.ts`.

### Choice Conditions

`if (expr)` conditions in choices are evaluated via `new Function` (`src/story/evalWhen.ts`). The expression is normalized before evaluation: `==`/`!=` → `===`/`!==`, and `and`/`or`/`not` → `&&`/`||`/`!`. String comparison like `tag == "value"` works as strict equality.

### Generated Files

`src/language/__generated__/` contains parser files generated by `langium generate`. Do not edit these manually — regenerate with `yarn langium:generate` after modifying the grammar.

## Design Decisions

### Grammar: delimiter-based, not indentation-based

초기 구현은 `IND2`/`IND4`/`IND6`/`IND8` 고정 터미널로 들여쓰기 수를 하드코딩했다. Langium은 `IndentationAwareTokenBuilder`(INDENT/DEDENT 토큰)도 제공하지만, 이 DSL은 이미 씬 바디와 액션 블록에 `{}`를 사용하고 있어 INDENT/DEDENT와 섞으면 구조가 복잡해진다. 대신 `choices: { }` 명시적 구분자를 도입해 파서가 들여쓰기 없이도 구조를 결정할 수 있게 했다. 결과적으로 `IND*` 터미널과 `indentationDiagnostics.ts` 수동 검증이 모두 제거됐다.

**`vars:`는 `{}`를 쓰지 않는 이유:** `VarLine`은 `ID '=' value NL` 패턴으로 씬 선언(`ID '{'`)과 완전히 구별된다. `{}`가 없어도 파싱이 명확하고, YAML/TOML 스타일의 단순 key-value 선언에는 `{}`가 오히려 노이즈다.

### ScriptHead vs ScriptToken 구분

`TextLine`(`"..."`)과 `ScriptLine`(스크립트)을 구별하기 위해 `ScriptHead`는 STRING을 제외한다. `ScriptLine`의 첫 토큰이 STRING이면 `TextLine`으로 파싱된다. 두 번째 토큰 이후(`tailTokens`)는 `ScriptToken`을 사용해 STRING도 허용한다. `ActionScriptLine`도 동일한 전략으로 `ActionTextLine`과 구별된다.

### choicesAt — post-step 인코딩

씬에 `choices:` 뒤에 스텝이 있을 때(`Option B 패턴`), `Scene.choicesAt` 필드로 "선택지가 표시되는 stepIndex 슬롯"을 기록한다.

- `stepIndex < choicesAt` → 선택 전 스텝 (`steps[stepIndex]`)
- `stepIndex === choicesAt` → 선택지 표시 (`isDone = true`)
- `stepIndex > choicesAt` → 선택 후 스텝 (`steps[stepIndex - 1]`)

`storyReducer`와 `engineDerived`에 `resolveStep(scene, stepIndex)` 헬퍼로 통일. 단, 순환 의존성 방지를 위해 `storyReducer` 내부에 같은 로직을 로컬로 복사했다.

### 무명 씬 (`__anon_N`)

선택지 액션 블록 `{ }` 안에 텍스트 라인이 있으면, 파서(`astToStory.ts`)가 컴파일 타임에 `__anon_0`, `__anon_1`, ... ID의 씬으로 분리하고 `choice.script`를 `jump("__anon_0")`으로 교체한다. 엔진은 일반 씬과 동일하게 처리하므로 런타임 변경이 없다. 텍스트가 없는 순수 스크립트 블록은 무명 씬을 만들지 않고 스크립트 문자열을 그대로 반환한다.

### DSL Syntax Reference

```iyagi
vars:
  hp = 10
  alive = true

sceneId {
  "Quoted line = text step"
  inc("hp", 1)              // Unquoted line = script step

  choices: {
    if (hp >= 5) "Option A" -> { jump("nextScene") }
    "Option B" -> {
      set("alive", false)
      jump("other")
    }
  }
  "Post-step after choices"   // runs after a choice is made (choicesAt)
}

inline { "text" "text2" }    // InlineScene: steps only, no script
```

`vars:` — indentation is cosmetic (any depth, or none). Ends when first scene starts.

`choices: { }` — explicit braces required. Each choice ends with `->` and an action block.

Action blocks (`-> { }`) with text lines inside are compiled to anonymous scenes (`__anon_N`) at parse time.
